\section{Instance Semantics and Guarantees}
\label{sec:semantics}
An instance selects an input domain and checks its admitted executions.
We formalize this meaning through interfaces for execution, observation,
and obligation generation.

\subsection{Instances and selected observations}
A concrete configuration $\sigma$ contains the C environment, heap, control
location, and call stack. A logical environment $\eta$ assigns values to
typed logical variables. We write $z=(\sigma,\eta)$; root entry bindings in
$\eta$ remain fixed during execution. The interpretation $\Gamma$ supplies
logical definitions, memory predicates, and the target layout.

\begin{definition}[Specification instance]
An instance is $I=\langle c,R,E,\theta,\mathcal B,\Gamma,b\rangle$, where
$c$ is the body, $R$ and $E$ its entry and return assertions, $\theta$ a typed
partial binding, $\mathcal B$ the selected observation boundaries, and $b$
the execution and proof-search budgets. Its input domain is
\begin{equation}
\dom=\{(\sigma,\eta)\mid
       \eta\models\theta\land(\sigma,\eta)\models_\Gamma R\}.
\end{equation}
\end{definition}
Checking an instance quantifies over all of $\dom$. Fixing a stored value
can leave its address and other inputs symbolic. An entry witness establishes
$\dom\ne\varnothing$; it does not replace the domain by that witness.
Stronger bindings restrict the domain, but need not preserve nonemptiness.

Heap assertions describe exact owned resources, with separating conjunction
interpreted by disjoint composition~\cite{reynolds2002separation}.
At auxiliary boundaries, the resolved check includes the exact local-storage
frame of Section~\ref{sec:boundaries}. Let $\mathcal B_\Gamma(z)$ be the
finite list of resolved checks selected at $z$, including these frames.
For a finite trace $\tau=z_0\cdots z_m$, define
\[
\mathsf{Observe}_{\mathcal B}(\tau)
 =\mathop{\bigoplus}_{i=0}^{m}
   [(z_i,A)\mid A\in\mathcal B_\Gamma(z_i)].
\]
Concatenation retains order and repeated visits. Resolving a call boundary
uses that invocation's logical bindings while preserving the caller's entry
values. A checked execution is safe, satisfies every selected observation,
and satisfies $E$ on return.

\subsection{Execution and observation interfaces}
A symbolic configuration $\langle\ell,P,K,U,\Omega,b\rangle$ contains the
control location, represented state assertion, call context, pending
observations, accumulated obligations, and remaining budget.
Write $\llbracket P\rrbracket_\Gamma$ for its represented states and
$\to_c$ for the concrete program transition relation.

At a nonterminal program step with successors $P_1,\ldots,P_k$, the executor
must establish progress, safety, and coverage:
\begin{equation}
\label{eq:coverage}
\begin{split}
&\forall z\in\llbracket P\rrbracket_\Gamma.\;
  \mathsf{Safe}(z)\land\exists z'.\,z\to_c z',\\
&\forall z,z'.\;
  z\in\llbracket P\rrbracket_\Gamma\land z\to_c z'
  \Rightarrow z'\in\bigcup_j\llbracket P_j\rrbracket_\Gamma.
\end{split}
\end{equation}
An unresolved guard retains each successor whose infeasibility has not been
established. Coverage may overapproximate executions for acceptance;
negative evidence additionally requires realizability.

An observation is an administrative transition:
\begin{equation}
\label{eq:observe}
\frac{Q=\mathsf{Resolve}_{\Gamma,K}(A)*F_{P,A}}
 {\langle P,A::U,\Omega\rangle
  \xrightarrow{\mathrm{observe}}
  \langle P,U,\Omega\cup\{P\vdash Q\}\rangle}.
\end{equation}
The omitted program context remains unchanged. The continuation retains $P$,
rather than replacing it with $Q$ or requiring the new obligation to hold
before execution proceeds.

A finite execution tree contains program-step, observation, normalization,
terminal, and unfinished nodes. Terminal nodes establish safety, the return
assertion, and absence of further program transitions. Normalization preserves
the joint state/value relation of Section~\ref{sec:normalization}.
Reaching an execution bound produces an unfinished leaf.
A tree is \emph{boundary-complete} when every selected boundary along each
represented execution is paired with an observation node whose antecedent
contains the reached state and whose consequent is the correctly resolved
check. This connects the selected schedule to the obligation inventory.

\subsection{Reference trace preservation}
\label{sec:noninterference}
The reference monitored semantics records observations without consulting
their truth.
\begin{theorem}[Erasure and lifting]
\label{thm:erasure}
For any resolved finite boundary schedule $\mathcal B$ and state trace
$\tau$ from $z$ to $z'$, a monitored execution with state trace $\tau$
exists if and only if $\tau$ is a program execution from $z$ to $z'$.
Its observation list is exactly $\mathsf{Observe}_{\mathcal B}(\tau)$.
\end{theorem}
\begin{proof}
Induct on the finite execution derivation. Each monitored step retains the
program transition and appends the selected observations. Erasure removes
that list; lifting reconstructs it. No rule requires an observation to hold.
\end{proof}
Changing an observed assertion therefore does not filter program executions
in this reference semantics. Erasure, lifting, and the observation inventory
are mechanized in \texttt{ObservationTrace.v}.

\subsection{Acceptance and negative evidence}
\label{sec:verdicts}
\begin{theorem}[Nonvacuous instance acceptance]
\label{thm:acceptance}
Suppose a finite, boundary-complete execution tree has root domain
$\dom\ne\varnothing$, satisfies the execution and normalization interfaces,
and has no unfinished leaf. If all generated obligations are valid, every
execution from $\dom$ terminates safely, satisfies $E$, and satisfies every
selected observation.
\end{theorem}
\begin{proof}
Induction on the tree establishes safe termination. Program-step coverage
places every concrete successor in a child subtree; normalization and
observation nodes preserve the represented continuation. Terminal obligations
establish the return assertion. Boundary completeness and valid observation
obligations establish each selected check. Entry nonemptiness supplies
nonvacuity independently.
\end{proof}
\texttt{InstanceChecking.v} mechanizes the finite-tree safety and termination
argument; \texttt{ObservationTrace.v} establishes satisfaction of a discharged
observation inventory. Their connection to C execution and the generated
boundary inventory is an implementation obligation.

A confirmed execution violation has existential meaning:
\begin{equation}
\label{eq:violation}
\exists z_0\in\dom,z.\;
z_0\to_c^*z\land\mathsf{Bad}_{E,\mathcal B}(z),
\end{equation}
where badness is an unsafe state, a violated selected check, or a return
state violating $E$. For a path obligation $P\vdash A$, a positive proof
establishes validity for every represented state. A negative proof refutes
that obligation. To obtain Equation~\eqref{eq:violation}, its violating state
must also be realizable from $\dom$: an overapproximation may contain
unreachable countermodels. A failed proof attempt establishes neither polarity.
