\section{Discussion}
\label{sec:discussion}
\paragraph{Choosing a test oracle.}
Runtime checking provides immediate feedback when a contract has an executable
interpretation. Proof-based testing extends that workflow to original
mathematical assertions and reuses the specification's lemmas. Its cost
therefore depends on both the execution and the proof route. The spatial read
cases show how improving automatic discharge can remove proof work while
preserving the execution and its obligations. Quantified contracts illustrate
where proof completion remains useful.

\paragraph{Agreement between strategies.}
For a fully verified modular specification, every legal boundary post-state
satisfies the verified continuation, even when a summary admits values that
the implementation never produces. Theorem~\ref{thm:mode-correspondence}
therefore proves common PASS for completed decisions without requiring equal
states or two-way simulation. Verification must cover the entire selected
specification, and instance construction must preserve the verified facts
in every original VC. Open continuation obligations fall outside this
premise. Solver incompleteness or execution limits may still leave a test
UNKNOWN; partial correctness does not prove termination.

\paragraph{Validity of the comparison.}
The selected cases explain mechanisms and do not estimate their prevalence
across projects. Contract pairs must agree on integer widths, ownership,
aliasing, and logical definitions. The recorded read discrepancy concerns
32-bit signed negation; no pointer-layout conversion is involved. General
C comparisons additionally need matched target layouts and compiler settings.
Candidate preconditions also affect which inputs are admitted, so expected
behavior and input selection must be fixed independently of those candidates.

\paragraph{Scope of the guarantees.}
The Rocq development establishes reference observation semantics and the
stated execution-tree interfaces. The implementation additionally relies on
C-to-VC correspondence, complete successor and boundary generation, and the
selected memory interpretation. Automatic results trust the solver encoding;
proof certificates check their exported propositions and admitted assumptions.
These dependencies are recorded with the evidence rather than inferred from
a single success label. Finite instance acceptance covers its selected domain;
full verification covers the original precondition.
