\section{Discussion}
\label{sec:discussion}
\paragraph{Where the capability pays off.}
A developer with proof-oriented contracts and supporting lemmas can specialize
logical data and reuse the verifier to execute and check the instance symbolically.
Symbolic addresses and owned resources supply the test heap; the workflow requires
no native allocation harness. The least-root instance
illustrates the tradeoff: proof completion retains the quantified formula;
runtime checking uses a finite reformulation. On the common executable fragment,
Fulminate provides complete negative feedback for the paired mutants, whereas
\tespec{}'s automatic results remain unresolved. Proof construction and replay
are therefore central costs of the additional oracle capability.

\paragraph{Contract debugging and contract quality.}
The supplied Require and binding define $D_\theta$. Comparing candidate
specifications requires a behavior population fixed independently of those
candidates: an over-strong Require could otherwise remove problematic inputs.
Such a study should freeze initial heaps and positive/negative labels, record
entry rejection, and check negative examples with the intended polarity.
The current evaluation measures instance-checking capability and mechanisms.

\paragraph{Validity and transfer.}
The programs and proof groups were selected during development. Common-fragment
pairs control logical input data and C bodies; the least-root formula isolates
one assertion-translation barrier. These results establish the reported
capabilities on those subjects. Their frequency and proof effort across projects
need held-out predicate families and programs. Imported predicates can still
block reads or leave entry existence unresolved, as the original-library runs
show. Complete C-to-VC refinement remains an implementation obligation beyond
the mechanized reference interfaces.

Native differential runs use defined C executions. Architecture-sensitive
comparisons require matched widths, layouts, ownership, and aliasing: the
packaged executor models a 32-bit target while the native host is x86-64.
The original allocator reproduction is retained in the supplementary record
with its own budgets and target conditions. It supplies baseline artifact
coverage independently of the paired results.

The archived timings are single runs, some concurrent with other proof work.
They separate replay from construction cost and support the reported absolute
measurements. Comparative speed and proof-agent success require repeated
isolated runs, fixed libraries, and fixed budgets, as specified in the study
protocol. Unsuccessful proofs, unsupported inputs, and unresolved intermediate
baseline translations remain in the evidence inventory.
