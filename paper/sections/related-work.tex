\section{Related Work}
\label{sec:related}
\paragraph{Executable separation-logic specifications.}
Separation logic describes disjoint ownership of mutable
structures~\cite{reynolds2002separation}. CN verifies systems C using
separation-logic refinement types~\cite{pulte2023cn}; Fulminate translates
ownership and functional assertions into runtime checks~\cite{banerjee2025fulminate}.
Bennet generates compatible heap inputs~\cite{aamer2025bennet}.
Code-Specify-Test-Debug-Prove integrates partial contracts, loop-invariant and
lemma testing, and ghost arguments~\cite{aamer2026workflow}.
The CN workflow already unifies specification syntax across testing and
verification and supports intermediate checks. Its testing path executes an
instrumented binary on concrete heaps; \tespec{} reuses symbolic execution
to explore a partially instantiated logical heap domain.
\tespec{} extends the shared-specification workflow to a proof-capable test
oracle for assertions that remain mathematical
propositions after specialization: residual formulas over the symbolic heap
are checked in their original proof logic. The least-root comparison makes
this distinction concrete through an original formula and a proved executable
rewrite. SLICK supplies runtime separation-logic checking~\cite{nguyen2008slick},
and CSF uses separation-logic preconditions for concolic heap
testing~\cite{pham2019csf}; these approaches further establish heap-aware
execution as shared ground.

\paragraph{Testing declarative properties.}
QuickCheck tests executable properties~\cite{claessen2000quickcheck}; QuickChick
connects property-based testing to foundational proofs and derives generators
and semi-decision procedures for supported inductive
relations~\cite{paraskevopoulou2015quickchick,paraskevopoulou2022computing}.
COINS specializes Rocq specifications on trusted examples and checks concrete
proof obligations~\cite{yang2026coins}. \tespec{} connects this style of oracle
to program-derived symbolic heaps and selected internal boundaries, with
explicit execution coverage and observation preservation. VERINA evaluates
specifications through positive and negative tests~\cite{ye2026verina}; SpecRL
uses rejected negative behaviors, including materialized side effects, as a
completeness signal~\cite{huang2026specrl}. FormalBench and MutDafny assess
specification strength using mutation~\cite{lecong2025formalbench,amaral2026mutdafny}.
Candidate-quality evaluation additionally requires the independently fixed
behavior population discussed in Section~\ref{sec:discussion}.

\paragraph{Symbolic verification and proof infrastructure.}
QCP already combines symbolic execution, separation-logic reasoning, and
interactive Rocq proofs~\cite{wu2026qcp}; CN also has a Rocq lemma
translation~\cite{yin2025cnrocq}. \tespec{} reuses this proof infrastructure.
Its instance discipline executes bodies and loops and checks candidate summaries
on private copies, preserving the actual state for later observations. Joint
heap/value normalization and exact local frames maintain that discipline through
state representation changes. The proof controller then checks the complete
original instance interface and its admitted assumptions. This combination
connects partial input domains, stateful observations, and scoped evidence for
each complete result.
