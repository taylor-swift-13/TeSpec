\section{Related Work}
\label{sec:related-work}
\paragraph{Runtime testing of separation-logic specifications.}
CN uses separation-logic refinement types to verify ownership and functional
properties of systems C code~\cite{pulte2023cn}. Fulminate gives CN specifications
a computational interpretation, compiling them into C checks that track
ownership transfer during execution~\cite{banerjee2025fulminate}. Bennet derives
randomized generators for heaps satisfying CN preconditions~\cite{aamer2025bennet};
Darcy combines randomized choices with SMT constraints in a broader
code--specify--test--debug--prove workflow~\cite{aamer2026workflow}.
\tespec{} pursues the same early-feedback objective through a proof-based
oracle: it symbolically executes a selected input domain and retains
assertions as logical obligations. Fulminate is the direct runtime comparator.
Bennet and Darcy address input generation and use Fulminate to check the
resulting executions, rather than providing independent fixed-input oracles.

\paragraph{Testing declarative specifications.}
QuickChick integrates property-based testing with Rocq and provides foundations
for relating executable testing components to logical
specifications~\cite{paraskevopoulou2015quickchick,paraskevopoulou2022computing}.
COINS instantiates relational specifications on supplied input/output examples
and uses Rocq proofs to establish that those examples are
admitted~\cite{yang2026coins}. This is particularly close to \tespec{}'s treatment
of assertions without convenient executable checkers. COINS evaluates a relation
on supplied behaviors, while \tespec{} executes a C implementation and generates
obligations for safety, internal observations, and postconditions. A direct
instance proof oracle on the shared pure fragment therefore isolates the
benefit of execution-derived observations. QuickChick is complementary when
an executable checker is available.

\paragraph{Symbolic testing and complete verification.}
Gillian provides a memory-model-parametric symbolic execution framework, with
C instances supporting symbolic testing and separation-logic
verification~\cite{santos2020gillian,maksimovic2021gillian}. It is an independent
symbolic-execution comparator for separating the contribution of \tespec{}'s
observation and proof workflow from symbolic execution itself.
\qcp{}~\cite{wu2026qcp} and CN provide the full-verification comparison.
That comparison checks each primary program's original, uninstantiated
contract. It measures the cost of establishing the original contract alongside
the cost of checking selected instances, without reinterpreting modular
verification under a fixed input as a test execution.

\paragraph{Semantic foundations and obligation solving.}
Exact separation logic distinguishes coverage of program behavior from
establishing that a reported behavior is reachable~\cite{maksimovic2023exact}.
Verification-preserving inlining studies conditions under which expanding
calls and loops preserves verification in automatic separation-logic
tools~\cite{dardinier2023inlining}. These results motivate explicit treatment
of coverage and realizability. Foundations for translational separation-logic
verifiers formalize interfaces between source reasoning, intermediate semantics,
and verification backends~\cite{dardinier2025foundations}. \tespec{}'s reference
interfaces similarly separate generation from discharge, while specializing
the checked domain and retaining observed states. Finally, separation-logic
SMT procedures already decide substantial logical
fragments~\cite{reynolds2016sl}. Spatial SMT applies this direction to supported
finite-heap obligations; proof-assistant completion handles additional reasoning.
