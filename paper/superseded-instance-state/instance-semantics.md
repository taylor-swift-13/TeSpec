# teSpec 的实例状态与符号执行语义

本文定义展开与不展开规约测试的共同状态、实例化、表达式求值及状态同步规则，并说明当前 C 实现的对应关系。实现位置是 sac 的符号执行器；teSpec 调用该二进制。

## 1. 语义对象与任务

设程序位置为 ℓ，程序变量环境为 ρ，C 内存为 h，逻辑变量解释为 η。具体状态为 σ = (ρ,h,η)。空间断言按 QCP 的内存模型解释，`*` 表示堆的分离合取；普通逻辑合取 `∧` 中的两个断言解释在同一个堆上。

函数规约写成 `{R(a₀,w)} f(a) {E(a₀,w,r)}`。a₀ 是入口参数的逻辑快照，w 是 With 变量，r 是返回值。用户提供有类型的部分绑定 θ₀。指针地址通常保留为符号值，数组、链表、树等结构的逻辑内容可用构造项绑定。

在逻辑公式中使用 θ₀ 时，指它的等式图，即所有绑定 `x ↦ v` 对应的等式 `x=v` 的合取。

测试有两个独立目标：

1. 初始存在性：`∃η,h. R[θ₀](η,h)`。
2. 在这组输入对应的状态集合上验证执行义务：`{R[θ₀]} body {E[θ₀]}`。

剩余符号在第一项中用于寻找存在见证，在第二项中表示所有满足 Require 的解释。一个 SAT 见证不自动成为执行路径的输入绑定。

## 2. 每个程序点的乘积状态

每个活跃分支维护：

```
T = ⟨ℓ, P, I, θ₀, Ω, m⟩
I = ⟨ν, L, K, M⟩
```

- P：QCP 的当前符号断言，包含纯约束、局部变量地址映射、空间谓词和量词。
- I：当前实例信息，随当前分支和程序位置变化。
- ν：当前实例观察的版本标识。
- L：程序变量 ID 到当前符号存储位置的映射。
- K：当前有效的逻辑等式。
- M：当前有类型的内存信息，包括单元、数组及未展开空间谓词。
- θ₀：不可变入口绑定。
- Ω：尚未关闭的安全性、蕴含和后条件义务。
- m：expand 或 no-expand。

M 使用 QCP 的 Separation 数据结构。符号地址保持符号身份；M 不分配宿主机地址。对不透明谓词，I 可以保存其符号应用，不假定其内部内容已经确定。

I 的解释 γ(I) 是这些观察在当前状态上的一致性约束，不额外消耗另一份堆。概念上的联合解释为：

```
⟦T⟧ = { σ | σ ⊨ P ∧ γ(I) ∧ θ₀ }
```

当前实现采用物化形式：在需要保留实例信息的断言转换中，先把合法的实例替换和路径事实加入后继公式，再同步 I。因此同步边界处有 `P ⊨ γ(I)`。P 与 I 是同一语义状态的两种接口，不允许用 `P * γ(I)` 重复声明内存。

**关键不变量：每次使用 I 前，它必须对应当前 P 的版本。先把 P 放缩、再只从弱化后的 P 提取信息是不够的；跨断言的实例传递必须发生在放缩之前。**

## 3. 实例化与求值的区别

逻辑实例化 `Subθ(F)` 是按逻辑变量 ID 进行的、避免变量捕获的有类型替换。输入绑定只作用于入口快照或相应 With 变量。新调用、新循环归纳状态和内层量词产生的变量具有独立身份。

程序点实例化使用 θ₀ 与当前 I：

```
Inst(T,F) = N(Subθ₀(Resolve(F,L,K,M)))
```

Resolve 将程序表达式中的变量、合法内存读取和当前逻辑值解析为当前值项。规范注解的解析和 QCP 匹配器负责程序变量到逻辑项的对应，不按变量名做字符串替换。内存读取的合法性仍产生 QCP 原有安全性义务。

N 是共享求值与化简模块。它执行已知算术、布尔和列表操作，对能够访问定义且满足展开条件的逻辑函数、谓词求值。不能求值的子式原样保留，预算不足保留 residual。

化简正确性的目标是：

```
θ₀ ∧ Γ ⊨ F ↔ NΓ(F)
```

其中 Γ 只包含当前分支有效的事实。对于引入新鲜变量的定义展开，右侧取相应的存在闭包。C 运算的溢出、除零、移位、宽度及浮点条件仍受原有执行语义约束，不能借助数学整数化简抹掉安全性 VC。

例如入口 `n₀=2, xs₀=[10,20]`，执行 `n++; p[0]=n;` 后，当前 n 为 3，当前数组内容为 `[3,20]`，入口列表 xs₀ 仍为 `[10,20]`。

## 4. 同步协议

普通语句的处理规则为：

```
P̂ = Materialize(P,I,θ₀)
(Praw, V) = QCPstep(c,P̂)
P' = N(Praw)
I' = Capture(P')
T' = ⟨ℓ',P',I',θ₀,Ω∪V,m⟩
```

Materialize 在实例信息已经写回 P 的实现形式下只需执行共享规范化。Capture 保存独立拥有的局部映射、等式和空间信息。

实现以同步边界和查询前刷新保证一致性，而非要求所有底层 QCP 数据结构都是不可变对象：

- 普通语句执行前后规范化并同步。
- 条件表达式执行及其副作用完成后同步。
- 定义展开、分支分裂、调用后条件与 frame 合并后同步。
- 底层替换、合并和主要写入接口使旧观察失效。
- 消费当前实例的匹配接口在使用前再次刷新，覆盖 QCP 策略内部直接修改公式的情况。

版本是观察版本，不是每个堆单元的 SSA 编号。当前实现重建 M，以整体失效代替精细别名依赖缓存。这样不会因为指针名称未变而复用旧内容。

## 5. 赋值与内存写入

标量赋值先求值右侧，再使用 QCP 写入左值对应的存储：

```
Eval(P,I,e) = (v,V)
P' = N(StoreQCP(P,loc(x),v))
I' = Capture(P')
```

内存写入 `*a=e` 使用相同规则。别名由 QCP 的地址等式和空间匹配处理。无法确认合法写入时保留相关义务或报告工具无法执行该操作，不把写入静默忽略。

例如 `p=q ∧ p↦3` 执行 `*q=4` 后，当前实例必须反映 `p↦4`。旧的 `p↦3` 不能作为当前内存事实参与后续实例化。入口值的独立逻辑快照仍可存在。

## 6. 分支与合并

条件产生不同后继：

```
Ttrue  = Sync(P ∧ guard, I)
Tfalse = Sync(P ∧ ¬guard, I)
```

每个分支拥有独立 I；物理复制必须深拷贝其内存和等式观察。确定为假的分支可以删除；无法判定的分支保留。

不展开模式的普通断言按各个入边分别实例化，即使它们共用一个 QCP 分支标签。由此保留 `b≠0 ⇒ x=4` 与 `b=0 ⇒ x=3` 的相关性。如果确实构造公共后继，只能使用所有入边一致的替换，或显式保留析取。

## 7. 普通 Assert 的中间实例化

对于目标注解 A，从当前 I 和 P 中匹配目标存在变量，得到候选 θc：

```
θc = MatchQCP(P,I,A)
A* = N(A[θ₀][θc] ∧ Pure(P))
VC = P ⊢ A*
P' = A*
I' = Capture(P')
```

这里 Pure(P) 是当前分支的纯事实。普通断言不执行内存写入，所以这些关于逻辑值的事实可以保留。目标中的局部值和逻辑内容通过 QCP 的结构匹配获得对应关系。

对目标存在变量的合法实例化满足 `A* ⊢ A[θ₀]`，因为可以用候选项进行存在量词引入。匹配只提出候选，不充当证明。生成的 VC 必须包含已经实例化的目标；未关闭的 VC 留在 Ω，整体结果不能成为 PASS。匹配存在变量 `v↦P₀` 时，应先消去 v 的存在量词再替换，不能把 v 的量词改名成 P₀ 的量词。

例如：

```
P  : x↦3
A  : ∃v. x↦v ∧ v≥0
θc : v↦3
A* : x↦3
```

执行 `x++` 后下一次匹配必须得到 4。不能缓存某一源代码位置第一次到达时的 θc。

空间匹配使用 QCP 的统一匹配器，包括单元、数组、字段及空间谓词应用。匹配失败时保留未实例化的目标及其证明义务。定义不透明且目标省略了内容关系时，当前后端不能自动恢复该关系；这属于实例精度障碍，应保留 UNKNOWN 或 residual。

Which Implies 同样属于不执行写入的证明转换。先执行 QCP 原有局部规约处理，再以该入边的当前实例细化输出；发生实例替换时，额外生成从原状态到细化状态的蕴含 VC。原有 Which Implies 义务完整保留。真正的函数调用不应用这条规则。

展开模式的策略为：ignore 不以证明注解替换状态；check-preserve 在状态副本上检查，合并义务后继续原来的实际执行状态。

## 8. 函数调用

### 8.1 不展开模式

1. 从当前 (P,I) 求值实参。
2. 为契约逻辑变量、形参与后置存在变量创建正确作用域的名字。
3. 匹配调用前条件，生成 `P ⊢ Rg[θg] * F` 等 QCP 义务。
4. 使用同一组 θg 实例化 Eg，freshen 后置存在变量。
5. 后继为 `N(Eg[θg] * F)`，据此同步 I。

当前实例可以实例化调用输入和规约的 With 变量；契约允许修改区域的旧内存值不能跨调用保留。F 中的未修改区域正常保留。

`p↦3` 配合 `Require p↦v; Ensure p↦v+1` 得到 `p↦4`。若 Ensure 为 `∃w.p↦w`，当前内容就是新鲜 w。不能从函数体偷取 4，也不能继承旧值 3。

### 8.2 展开模式

有函数体时创建新鲜调用帧并执行函数体，在各程序点同步 (P,I)。返回值和实际内存修改回到调用者，清理局部存储。入口快照、调用帧与同名局部变量使用不同逻辑身份。

只有声明且有契约的调用回退到契约语义并记录事件；没有函数体也没有契约时报错。被测目标只有声明时，执行 specification-only 的 Require 检查，安全性与 Ensure 标为 NOT_RUN。

## 9. 循环

### 9.1 展开模式

每次到达条件、循环体和回边都有独立的当前实例观察：

```
(Pk,Ik) --guard--> body --step,N,Sync--> (Pk+1,Ik+1)
```

条件已定则选取对应分支，否则保留多条路径。break、continue、return 按 QCP 控制流传递相应分支状态。预算用尽报告 UNKNOWN。

### 9.2 不展开模式

区分入口、归纳和退出三个状态：

```
入口：    Pentry ⊢ J[θ₀]
归纳：    {J[θ₀] ∧ guard} body {J[θ₀]}
退出：    Pexit = N(J[θ₀] ∧ ¬guard)
```

分别维护 Ientry、Iind 和 Iexit。Iind 从不变式描述的任意迭代状态建立，不能从 Ientry 继承循环修改变量的入口常量。θ₀ 中的逻辑快照仍然有效。

例如入口 `i=0,n₀=2`，不变式 `0≤i≤n₀` 实例化为 `0≤i≤2`。归纳阶段的 i 保持符号化；退出时结合 `i≥2` 可恢复 `i=2`。

确定输入不意味着不展开分析中的所有中间值都确定：一个归纳程序点代表多次迭代，弱不变式或弱契约也可能对应多种结果。I 必须能表达这些符号关系。强行填写一个常量会改变验证问题。

## 10. Require 检查与结果

Require 检查在独立副本上进行，不读取后续状态 I。能够展开的定义和已知表达式先共享求值，然后检查纯逻辑、存储取值、布局、地址边界与分离关系。

必要条件编码的 UNSAT 可以排除原 Require；其 SAT 不能单独提升为完整 SAT。完整编码或经检查的完整见证才能报告 SAT。剩余空间谓词保留原存在性目标用于 ITP。

- 初始 UNSAT：INVALID，后续执行阶段 NOT_RUN。
- 尚未关闭的存在性或验证义务：UNKNOWN，并保留 VC。
- 自动关闭的 VC：auto；尚需外部证明的 VC：manual。
- 独立证书状态单独报告，含 Admitted 的文件不是证明证书。
- 普通蕴含失败不能直接当作真实可达执行的反例。

## 11. 正确性命题及论证结构

**同步保持性。** 若 QCP 原有执行步骤正确、N 保持等价、当前实例转换满足上述作用域和失效条件，则每个已同步后继的 I 都由该后继公式支持；满足前置状态并执行相应语句的具体后继包含在后继符号状态中，条件是 Ω 中的义务全部成立。

论证按转换分类：

1. 普通执行使用 QCP 的状态转换正确性；Capture 只观察其结果。
2. 化简使用等价性，替换使用变量身份与避免捕获条件。
3. 普通断言以加强后的目标生成蕴含 VC，故后继实例关系由同一义务支持。
4. 分支分别保存事实，合并取析取或公共事实。
5. 契约调用使用 QCP frame 规则和新鲜后置变量。
6. 不展开循环使用独立归纳状态，入口具体值不会成为未经证明的不变式。
7. 展开循环与调用按有限执行步骤组合；预算退出不产生成功结论。

这是实现应满足的相对正确性论证，前提包括 QCP、求值规则和内存编码的正确性。当前交付提供可执行回归及 ASan/UBSan 检查，尚未提供这些 C 模块的机器检查健全性证明。

## 12. 实现与复现

sac 文件位置：

- `include/SymExec/AsrtDef/AssDef.h`：每个 Assertion 拥有当前实例信息。
- `SymExec/AsrtDef/AssDef.c`：实例信息生命周期、深拷贝及失效。
- `SymExec/SymExec/InstanceContext.c`：入口绑定、当前观察、QCP 匹配与中间实例化。
- `SymExec/Utility/ExpressionNormalize.c`：共享求值及同步。
- `SymExec/middle_end/SymExecutor.c`：语句边界、按入边实例化断言、保持循环归纳作用域。
- `SymExec/SymExec/FuncCall.c`：调用匹配、后置变量 freshening、frame 与后继化简。
- `SymExec/SymExec/SpecTest.c`、`SymExec/JsonPrinter/JsonFormat.c`：可选程序点观察输出。

诊断参数 `--instance-trace --Json-output` 将语句和条件表达式前后每条分支的 P、当前内存、等式、源位置和观察版本写入 executor JSON。默认不输出完整轨迹，保持常规产物精简。ν 标识观察，不替代控制流节点或动态调用帧标识。

运行新增回归：

```bash
SAC_SYMEXEC=/path/to/symexec python3 SymExec/tests/run-instance-state-tests.py
```

测试包含正常结果与错误传播反例。预期 UNKNOWN 的反例通过，表示工具没有误报 PASS，并不表示其目标已经得到证明。完整示例烟测中的 UNKNOWN/ERROR 与回归测试是否满足预期分别统计。
