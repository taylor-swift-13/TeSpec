\begin{abstract}
Specification testing for C commonly compiles logical assertions into executable
checks and evaluates them during concrete program runs. Proof-oriented functional
specifications can contain quantified properties and abstract relations that
still require deduction after the input data are fixed. We present \tespec{},
which formulates specification testing as instance-specialized symbolic
verification. It reuses a verifier's symbolic execution, logical heap model,
and proof infrastructure to check the original assertions without a native test
execution or a separate executable monitor for residual properties. Partial
bindings define the input domain. Symbolic execution follows program bodies
and loops; annotations generate obligations on state copies. Joint heap/value
normalization and exact local frames preserve the information needed by later
checks. We mechanize observation noninterference and nonvacuous acceptance under
explicit coverage interfaces. A least-root instance checks all 27 obligations,
including a quantified intermediate assertion. The original quantified
postcondition is rejected by the tested CN runtime-testing configurations,
while a proved finite rewrite passes Fulminate. Complete proof-group checks take
124.45--140.12 seconds, excluding construction. The method unifies instance
testing and verification around the same symbolic execution and proof logic,
making mathematical functional specifications directly usable as test criteria.
\end{abstract}

\section{Conclusion}
\tespec{} formulates stateful specification testing as instance-specialized
symbolic verification, reusing the verifier's execution and proof infrastructure. A functional assertion can serve as a test criterion even when its
instance requires proof.
Partial bindings determine the input domain, program transitions determine the
states, and copied-state observations determine the proof obligations. Joint
normalization and exact local frames preserve the values and resources needed
by later checks. The least-root cases demonstrate direct checking of a quantified
return property and an intermediate assertion, while the paired common-fragment
results expose the cost in residual proof work. The resulting method connects
proof-oriented instance evaluation to the internal specification boundaries of C.
