\begin{abstract}
Logical specifications for C describe both functional behavior and ownership
of memory. Testing them presents two challenges: quantified properties can
remain non-executable after inputs are fixed, and modular verification can
abstract away the execution states needed to test an annotation. We present
\tespec{}, a method for proof-based testing of separation-logic specifications.
Typed input bindings select an instance domain. Symbolic execution follows
function bodies and loop iterations, while annotations generate obligations
on copies of the reached states. Automatic reasoning and proof-assistant
completion check those obligations in the original specification logic.
Joint heap/value normalization and exact local-storage frames preserve the
information observed by subsequent checks. We formalize the instance semantics
and mechanize reference trace preservation and nonvacuous acceptance under
execution-coverage interfaces. Comparative case studies expose a signed-integer
boundary violation missed by the recorded Fulminate configuration, demonstrate
proof completion for quantified contracts rejected by runtime instrumentation,
and examine automatic versus interactive discharge of spatial obligations.
The method makes proof-oriented contracts usable as test oracles while
retaining the program states and memory resources that those contracts describe.
\end{abstract}

\section{Conclusion}
\tespec{} connects execution-based feedback with proof-oriented C contracts.
Input bindings select the tested domain, actual program transitions determine
the observed states, and proofs establish their specified properties. Copied
observations, joint normalization, and exact local frames preserve this
connection through the verification infrastructure. The case studies show
why a useful oracle must account for arithmetic safety, original quantified
relations, and spatial ownership. The resulting workflow supports testing
with the same specifications and logical libraries used for full verification.
