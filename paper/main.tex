\begin{abstract}
Fixing a program's input does not necessarily make its logical
specification executable. A finite execution can leave quantified
properties and spatial ownership conditions to establish.
We present \tespec{}, a method for proof-based testing of separation-logic
specifications for C. The method uses execution to determine program
states and proof to check the specification at those states.
Inline symbolic execution follows function bodies and loop iterations under
selected input bindings; a modular strategy samples summary-admitted states. Inline annotations generate obligations on copies of
the reached states, allowing execution to continue with the values and
memory it produced. Automatic reasoning and proof-assistant completion
check these obligations in the original specification logic.
We formalize instance checking and mechanize trace-preservation, acceptance,
and conditional agreement between the two strategies for reference models.
Recorded case studies examine a signed-overflow violation missed by a
Fulminate configuration, original quantified contracts with equivalent
runtime controls, and spatial obligations resolved by automatic reasoning
or checked refutation. \tespec{} supports execution-based feedback from
proof-oriented contracts before full program verification is complete.
\end{abstract}

\section{Conclusion}
\tespec{} connects execution-based feedback with proof-oriented C contracts.
Input bindings select the tested domain, actual program transitions determine
the observed states, and proofs establish their specified properties. Copied
observations, joint normalization, and exact local frames preserve this
connection through the verification infrastructure. The case studies show
why a useful oracle must account for arithmetic safety, original quantified
relations, and spatial ownership. The resulting workflow supports testing
with the same specifications and logical libraries used for full verification.
