teSpec 论文审稿与针对性修改记录
日期：2026-10-12

核心定位
将规约测试定义为“对实例化输入域的符号验证”。复用验证器的符号执行、逻辑堆模型和证明基础设施，使原验证规约直接成为功能正确性判据。实例化后仍需演绎推理的量词和抽象关系，可以保留为证明义务。

与 CN 的准确区别
CN 已经统一规约语法及测试—验证工作流，其运行时测试路径将支持的规约编译为检查代码，在具体堆上执行仪器化程序。teSpec 的测试状态直接来自验证器中的符号执行，检查继续使用验证逻辑及证明库。不能把“CN 没有中间断言测试”“CN 没有 Rocq”或“CN 一定要求用户手写所有检查代码”写成差异。

一、已经发现并修改的问题

1. [主要 / novelty] 旧引言多次重复“复用原规约”，没有区分语法复用、逻辑复用和执行基础设施复用；核心贡献也容易被理解为把 ITP 接到符号执行后。
修改：标题、摘要、引言和结论统一为 instance-specialized symbolic verification；引言明确状态来源与判据两层复用。新增 CN runtime testing、COINS、QCP verification、teSpec 对照表。三项贡献落到方法语义、状态保持检查机制和能力/成本证据。

2. [主要 / 技术定位] 若把 heap-aware testing、intermediate checking 或 proof-based instance evaluation 单独作为首创，会与最近工作冲突。
修改：核对 CN PLDI 2026 原文、Fulminate 原文、COINS 论文主页、QCP 原文。明确复用基础与新增组合的技术问题：被测断言不能成为后续执行的假设；局部 frame、活跃值和堆必须保持关联。
来源：
- Code-Specify-Test-Debug-Prove: 用户工作区已有论文 PDF；DOI 10.1145/3808278。
- Fulminate: https://www.cl.cam.ac.uk/~pes20/cn-testing-popl2025.pdf
- COINS: https://proceedings.mlr.press/v306/yang26am.html
- QCP: https://arxiv.org/abs/2505.12878

3. [主要 / 证据逻辑] 旧结果流程图将对 VC 的负向证明直接映射为 FAIL，遗漏从符号状态到可达执行的证据接口，与正文的形式语义及归档负例范围不一致。
修改：重绘证据流程图，显式加入负向证据的 reachability gate。保留“checked VC refutation”与“admitted execution violation”的区别。正向完成仍要求入口存在、执行完整和全部选定义务成立。

4. [主要 / 实验叙事] 正文混合研究设计、安装过程、历史调试、多批不同分母的 smoke runs，读者难以知道每组数据回答什么问题。最新 PDF 已达 22 页，旧验证 JSON 仍写 10 页。
修改：正文重组为原数学性质、共同可执行片段、状态保持机制、工程覆盖四组证据。重新接入自动生成的 proof/paired/mechanism/regression 四张表。把旧长篇实现及评估记录完整保存在 supplement/*-development.tex。更新当前 PDF 的真实页数和验证信息。

5. [主要 / 数字与范围] least-root 的 26 与 27 个义务属于不同实例；44 个 relational-loop 义务、19 个 traversal 义务应从 manifest 读取。11 个合同配置对应 10 个程序体，不能把运行次数当样本数。
修改：正文显式说明 return-only 为 26、加入中间断言为 27；102 次调用、11 配置、10 程序体分别列示。全部证明组数量和 paired 表由归档证据生成。

6. [主要 / 负面结果解释] UNKNOWN 不是确认违反，回归期望全满足也不是检错率 100%。局部 residual VC 减少不等于新增完整 PASS。
修改：保留共同片段的 10/11 正例自动 PASS 和 11/11 变异 UNKNOWN、Fulminate 的 11/11 runtime violations；保留纯事实投影新增完整 PASS 为 0；说明 779 个预期负例包含不支持场景。将这些解释放在对应实验，而不在贡献陈述中反复防御。

7. [次要 / 图示] 旧主图以工具模块为中心，未说明原量词规约为何能直接测试。
修改：主图使用 least-root 的符号执行轨迹，显示输入域、五次循环观测、写入与返回，以及同一逻辑性质如何进入证明判据。两图保留共享 TikZ 源及独立矢量 PDF。

8. [主要 / 可复现性] 构建脚本依赖论文目录外的未提交审计 JSON；形式化源文件也已比旧 replay 多出两个 AffineOffsets 结论。
修改：所需审计摘要复制进 paper/evidence/audits/，表格生成只读取论文包。当前 theory 脚本纳入 ObservationTrace 并重放全部当前模块；当前 replay 与旧 86-statement archive 分别记录。

二、仍需要研究证据回答的问题

A. 目前最直接的原公式/可执行改写比较是一个 least-root 性质。若主张这一收益在真实功能规约中普遍存在，需要按固定规则选取独立项目和谓词族，统计原规约的完成率、改写工作量和证明工作量。目前正文只陈述已有能力。

B. 124.45–140.12 秒是完整 proof-group 的检查成本，不含构造证明的成本。若主张降低开发成本或自动化更强，需要固定库和预算，计入失败尝试，区分证明构造、检查和复用收益。现有文本不据此推导速度优势。

C. 中间量词负例已有完整 VC 反证，归档中尚未完成对应的可达执行反例证书。若将它纳入“确认检测到的执行违反”，需补上该证书或用匹配版本重新运行并冻结结果。

D. 抽象语义定理与 C 前端、布局解释、VC 生成器的完整精化证明是不同证据。当前结论明确保留接口条件，不能称整个实现已被端到端验证。

上述 A–D 是研究结论及其适用范围的问题；本轮写作修订不把它们伪装成已经完成的实验。它们也不否定已经展示的原规约检查能力。
