## 完整 CN 基线

来源为上游 [cn-runtime-testing 分支的发布前版本](https://github.com/rems-project/cn-tutorial/tree/c67da060a4741b7c49619578910ba81bd0d16fcc)，提交 `c67da060a4741b7c49619578910ba81bd0d16fcc`，日期 2024-11-22。[来源锁](fulminate-source-lock.json) 固定 Git tree、文件清单和 SHA-256。

| 分组 | 收录范围 | 计数单位 |
|---|---|---|
| CN 主程序 | `src/examples` 顶层全部 54 个非 broken C 文件 | 完整程序，保留原始 main、辅助函数与规约 |
| CN 补充输入 | 其余全部 22 个 C 文件 | 原始错误例、运行时例、双链表和 runway 输入 |
| 工业例 | 原始 pKVM buddy allocator 及已有变异 | 一个分配器，多条操作轨迹 |

`src/examples` 的 127 个文件全部逐字节保存，并附上游 README、变更说明和两个检查脚本。头文件和文本片段保留原有相对位置。54 个主程序的划分与论文报告的规模一致；此处完整性的依据是固定提交的 Git tree，补充输入也全部列入。原文的其他来源，如 VeriFast 和 Verifiable C，属于独立来源范围。

完整收录表示源文件与清单齐全。这个历史版本的 CN/QCP 逐例配对和重跑仍待完成；现代教程的已有移植记录单独链接，避免把另一个版本的结果归到原文件上。所有原始例子保留在覆盖分母中，编译错误、接口缺失、UNKNOWN 和超时分别报告。[当前阻碍](blockers.md) 列出具体程序和需要补齐的能力。

首批 [QCP 迁移与验证](qcp-migration/README.md) 已覆盖 12 个原始文件中的 25 个目标函数：原生 QCP 自动消解 13 个目标，11 个有剩余义务，1 个重复释放驱动被拒绝。teSpec 的 192 次重放全部为 UNKNOWN，具体区分外部接口、入口证明和调用绑定问题。该批次仍属于函数级覆盖，CN 同输入配对及未迁移函数继续保留待办状态。

## QCP / CAV 分类扩展

当前选择 32 个 QCP 目标函数、18 个 CAV 目标函数。不同函数可能来自同一源文件，报告同时按目标函数和来源文件族统计。具体选择逐项记录在 `policy.json`，现有未选中的标量或重复数组结果保留为历史对照。

| 类别 | QCP+CAV 目标数 | 主要问题 |
|---|---:|---|
| 算术与逻辑定义 | 4 | gcd、整除、幂与求和定义；量词及非线性义务 |
| 数组 | 13 | 内容保持、区域分离、形状谓词、全称性质和反例 |
| 动态规划 | 2 | house robber / knapsack 的全局最优性与未初始化 DP 区域 |
| 侵入式链表 | 1 | LiteOS 环形结构、哨兵与对象布局 |
| 链表 | 8 | 双向/多态结构、反转、拼接和排序 |
| 矩阵与指针表 | 3 | 连续矩阵、分离行、字符串表 |
| 队列 | 3 | 单链表、双链表、双列表表示与生命周期 |
| 查找排序 | 7 | 不存在性、置换、严格多数与多数组关系 |
| 字符串 | 4 | 终止符、逐字节等价和变换 |
| 结构体 | 1 | 字段布局、所有权与框架保持 |
| 树 | 4 | BST、父指针、AVL、union 表达式节点 |

分类扩展检验以下能力：

- **符号堆检查**：固定逻辑数据，保留地址关系；与同一输入的具体执行比较。
- **逻辑定义与量词**：保留原始关系，比较直接插桩、经过证明的等价翻译、自动求值和残留证明。
- **ITP 完成未决义务**：冻结自动阶段，再检查原始 VC 或其否定；报告确定结果增加量与完整成本。
- **原始注解检查**：单列入口/出口与所有边界两种实验，保留原始 Assert、Inv 和调用契约。
- **复杂内存和生命周期**：检查布局、递归所有权、分配、释放和操作轨迹；接口未实现时明确记录缺口。

这些是选例要检验的能力。数组、链表、动态分配本身也受 Fulminate 支持，不能仅凭含有这些特征就认定 teSpec 有优势。对照应使用同一程序、相同逻辑输入和语义对应的规约；保留双方成功、失败、UNKNOWN、错误和超时。

## 结果与版本

原有 `paper-cn-qcp/` 中的源文件、输入、变异、证明和历史结果保持原路径。新清单引用较新的 `review-20261014/` 以及各专项证据。旧 `expansion80` 是冻结的历史实验批次，不再控制新选集的总量。

六个机制对照继续保留，单列在 `retained_controls`；它们不增加上游程序数。CN 原版主程序、CN 补充 C 输入、QCP/CAV 目标函数和工业操作轨迹采用各自计数单位。

每项分别记录源文件、规约移植、配对输入、实际运行和证明状态。进入可比实验需要满足输入与规约对应条件；结果是否 PASS 不作为入选门槛。未配对项留在完整覆盖表，并给出具体原因。

## 检查与更新

在仓库根目录执行：

```sh
python3 benchmark/selection/build_catalog.py
```

检查会核对全部锁定文件、54/76 的完整性、每个选例的实验问题、来源和证据文件哈希，以及生成表是否过期。它不调用执行器、不修改文件。

更改选例理由或证据入口后，审阅变更，再生成清单：

```sh
python3 benchmark/selection/build_catalog.py --write
```

新增结果应放在独立运行目录并保留版本、ABI、二进制哈希、输入 ID 和资源预算。新结果引用到清单后再生成表，不改写冻结报告。仓库只保存测试输入、规约和必要接口；sac、编译器和 SMT solver 源码继续留在仓库外。

首批简单目标的状态已纳入总清单，见 [迁移目录](qcp-migration/README.md#简单函数批次)。来源覆盖、函数迁移及实际配对执行分别统计。
