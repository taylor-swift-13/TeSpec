# Modular 边界复用入口实例化（2026-10-20）

函数入口与 modular 边界共用输入快照应用、等式和别名传播、闭合列表归约、有限数组视图及完整具体状态检查。modular 不再因为状态中出现已有具体内容的数组谓词，就直接拒绝选值。

入口的值来自测试绑定；边界的确定值来自调用参数、已有状态与规约等式，新产生且未确定的整数值沿用已有有界候选搜索。这只是值的来源不同，不再各自实现等式/列表/数组有效性判断。

## 复用范围与状态保护

- `PreconditionCheck.c` 的公共内部归一化路径同时服务入口可满足性检查、普通可满足性查询及边界样本检查；复用 `InstanceContext` 和原表达式归一化器。
- `ExprNormalizeInstanceAssertion` 复用原来的表达式、列表和别名归一化，只关闭为 shape 谓词引入额外存在见证的步骤。
- 边界样本在私有副本中使用与入口相同的有限数组解释和具体堆检查；实际后继仍保留 QCP 数组谓词、类型化地址和 frame，只增加经过完整检查的候选等式。
- 入口 SAT 可以用私有存在见证证明有一个合法输入；边界样本必须记录实际采用的值。不能把 SAT 查询中临时补出的内容带回执行。因此只有长度的数组和未知外部谓词仍符号回退，不能默认为全零数组。
- 采样失败不打断 modular 执行；不覆盖已固定值，不修改不可变入口快照，不删除原始 VC。VC 范围参数独立；没有在线 ITP。

例如，入口及调用前后均含 `IntArray::full(p,2,[9,13])` 时，可以检查相同的两个元素与其余 frame 是否共同满足地址、类型和分离要求，保留原数组谓词继续读写。若调用只保证 `IntArray::full_shape(p,2)`，则不能声称内容仍是 `[9,13]`，也不能私自选择全零内容后标记为完整实例化。

新增测试覆盖内容已知的数组、采样关闭对照、shape 原样回退、重叠数组资源与长度不匹配。外部执行器源代码仍只在 sac 工作目录本地修改；teSpec 仅交付二进制、来源哈希、测试与评测证据，未提交或推送 sac。

## 回归与证明结果

- 21 组、900 对输入：inline 与 modular 采样 on/off 各跑空间 SMT OFF/ON，共 5400 次原生执行。与紧邻修改前版本比较，没有新增回归。
- inline 的 1800 次原生判定与原始 VC/Coq 文件字节一致；modular 采样关闭的 1800 次也一致。
- modular 采样开启时，7 个数组客户端、14 次执行的原始 Goal 增加了真实采样的地址约束；其他 1786 次 VC 文件一致。没有修改程序、规约、测试输入或预期。
- translation7 的两次新 Goal 重新完成原始整体 VC 与入口 SAT 的证明、Coq 假设审计和独立 coqchk；translation12 仍是 UNKNOWN。其余适用的旧证书按完整原始 VC 哈希复用。
- 四种 modular 配置每种最终均为 497 PASS、379 FAIL、1 UNKNOWN、23 个预期 ERROR。UNKNOWN 不计成功；本轮没有增加“完整程序组”的数量。
- Python unittest：471 项，456 通过、15 跳过；新增检查为 5 项。Ruff 检查通过。

新证明按一次执行计费，各执行包含全部残余 VC。先尝试原样复用旧证明时，固定数量的 intro 与新增地址前提不匹配；随后实际 gpt-6.1-sol 的第一次修改未通过编译，第二次修复成功。原样复用失败、所有实际模型调用和失败编译均保留并计入。两个执行共 4 次模型调用、306100 token。证明仅依赖原目标既有的 5 个类型/地址参数，没有新公理；入口 SAT 全局封闭。
